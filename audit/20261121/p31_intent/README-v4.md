## 1. 真实语料实测（第一次不用自己写的样本）

**DENY 3 个的实际身份**（逐条看过证据）：

| 技能 | 为什么 DENY | 分类 |
|---|---|---|
| `lgd-gate`（仓库根目录） | 把整个仓库当技能扫，含 _demo 与规则文本 | 边界假象，非真实技能 |
| `_demo\mitiga-style` | `open("~/.aws/credentials")` + `urlopen` | **故意构造的泄漏样例**（TP） |

即：**在 149 个真实技能上，DENY 层对"正常技能"的误报为 0**。
但必须说明：这 149 个里 30 个是自家仓库，样本仍有偏。

## 2. 真实语料暴露的 4 类误报机制（全部已修，均来自实测而非想象）

### 2.1 `f"{'月成本(USD)':>14}"` 被当成 `:>` 截断（destruction 全线误报）

第一版把 shell 的 `:>` 写进 destruction 正则，Python 格式化对齐符 `:>14` 命中。
一个成本估算器被判"破坏性操作 → DENY"。**已删掉该 token**。

### 2.2 文档里的安装命令被当成真实行为

`README.md:16 curl -fsSL https://raw.githubusercontent.com/...` 让 `env-var-audit`、
`changelog-draft-gen` 等被判"下载 + 执行 → DENY"。
**已把能力抽取拆成 code / doc 两套**：代码里的能力才能 DENY，文档描述最高 REVIEW（D01–D03）。

### 2.3 检测器悖论：安全工具自己被判恶意

`skill-admission-gate` 的 `scan_skill.py` 里写满规则签名：

```python
("EXF-01", "BLOCK", "读取私钥/凭据文件", r"id_rsa|\.ssh/|\.aws/credentials|...")
```

引擎把"签名文本"当成"真的在读密钥 + 真的在发出去" → DENY。
**已修：含原始字符串 `r"`、`re.compile`、`Regex` 的行视为规则定义，跳过。**

### 2.4 纯提示词技能被判 UNKNOWN（fail-closed 用错地方）

27 个技能没有可执行代码（纯提示词），被判 UNKNOWN → 按不可放行处理。
**新增 `PROMPT_ONLY` 档**：无代码可执行，风险面只剩提示注入（由规则层 md 扫描负责）。
`UNKNOWN` 从此只用于"读不了/解析失败"。
